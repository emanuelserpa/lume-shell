# Zen Browser — temas nativos e investigação

O Zen usa seu próprio **Editar tema**. Por decisão do usuário, o Quickshell
não gerencia o tema do navegador: o adaptador experimental foi removido,
incluindo os comandos `zen-enable`, `zen-status` e `zen-disable`, a geração
de CSS e os testes específicos. As correções de concorrência dos demais
adaptadores de temas permanecem.

## O que foi investigado

A investigação de 5 de outubro de 2026 conferiu o código empacotado do Zen
**1.22.3b** e o upstream no commit `dade90ac363e0614753e800e85270e8e6a4df570`.

O [editor nativo](https://github.com/zen-browser/desktop/blob/dade90ac363e0614753e800e85270e8e6a4df570/src/zen/spaces/ZenGradientGenerator.mjs)
monta `workspace.theme` com `type`, `gradientColors`, `opacity` e `texture`.
Cada cor pode incluir algoritmo, luminosidade, posição e indicação de cor
primária. A edição chama `saveWorkspace` e atualiza o gradiente da janela.
Alterar apenas `zen.theme.accent-color` não substitui esse conjunto.

O adaptador removido definia variáveis em `:root`. O Zen, entretanto, aplica
os gradientes diretamente em `#zen-browser-background` e
`#zen-toolbar-background`. Valores definidos nesses elementos prevalecem
sobre os herdados da raiz, mesmo quando a declaração ancestral usa
`!important`. Isso explica uma incompatibilidade concreta do CSS gerado,
sem comprovar todos os fatores envolvidos na falha visual relatada.

A [persistência de sessão](https://github.com/zen-browser/desktop/blob/dade90ac363e0614753e800e85270e8e6a4df570/src/zen/sessionstore/ZenSessionManager.sys.mjs)
guarda os workspaces em `spaces` no arquivo comprimido
`zen-sessions.jsonlz4`, junto com dados de abas e outros elementos da sessão.
Na versão inspecionada, a leitura de `zen_workspaces` em banco serve à
migração, não à persistência principal atual.

Não foi identificada uma API pública externa para o editor nos módulos
examinados. Editar o arquivo de sessão com o navegador aberto pode conflitar
com seu estado em memória e suas gravações. Não foi implementada integração
com esse arquivo, nem deve ser tratado como arquivo independente de tema.

## Uso atual

Escolher as cores pelo **Editar tema** do próprio Zen. Trocas de tema do
Quickshell não atualizam os temas dos workspaces. A integração GTK do sistema
não comprova que a interface do navegador acompanha a paleta.

Usar `about:support` para localizar o perfil ativo, tanto na instalação
nativa quanto no Flatpak. Na máquina investigada, o perfil foi encontrado em
`~/.config/zen`; não assumir `~/.zen` nem um nome fixo de perfil.

## Limpeza de instalações do adaptador antigo

A remoção do código não altera perfis pessoais nem remove customizações do
usuário. Se o adaptador antigo foi ativado em outra instalação:

1. Abrir a pasta do perfil por `about:support` e fazer backup do CSS existente.
2. Remover somente este bloco de `chrome/userChrome.css`, se estiver presente:

   ```css
   /* Quickshell Zen: begin */
   @import url("quickshell-theme.css");
   /* Quickshell Zen: end */
   ```

3. Remover `chrome/quickshell-theme.css` somente se for o arquivo gerado pelo
   adaptador, identificado por `Generated by Quickshell Zen adapter`.
4. Preservar os demais estilos e o backup `userChrome.css.quickshell-backup`.
   Não restaurar o backup inteiro se houver alterações pessoais posteriores.
5. Reabrir o navegador. A preferência de CSS pode permanecer habilitada se
   outras personalizações dependem dela.

O antigo `$XDG_STATE_HOME/quickshell/zen-theme.json` (fallback
`~/.local/state/quickshell/zen-theme.json`) e uma eventual entrada `zen` em
`adapters.json` são ignorados pelo código atual. Não é necessário removê-los
para interromper a integração.

Os testes do experimento validavam arquivos e backups, não a aparência do
navegador. A integração não foi validada visualmente e não deve ser descrita
como funcional. A investigação e esta remoção não alteraram arquivos de
sessão, preferências nem estilos pessoais do Zen.
